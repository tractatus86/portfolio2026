Method · multi-model debate

Moral Simulation

A method for having several AI models, each given a different role, argue a question with a built-in tension, to produce an insight no single answer gives. Started from Walter Benjamin on AI-flooded creative content.

Goal: have several AI models, given different roles, produce an insight beyond a single answer (from the playbook: "Running a Debate Experiment"). The method is reusable; Run 000 is the only run so far.

Why its own project: it began inside Theoretical Research (2026-11-05). That project later grew into the home for theme creation that serves the whole operation, so on 2026-11-16 the Owner split the debate method out. Concepts and the log of artists, works and ideas stayed in Theoretical Research.

Concepts the experiment started from

All three come from Walter Benjamin; they live in Theoretical Research and are cited here. | Concept | What it is | How Run 000 used it | |---|---|---| | Aura | Unique presence of an original artwork; weakened by mechanical reproduction ("The Work of Art in the Age of Mechanical Reproduction") | Models disagreed on whether AI content kills aura or only exposes how exclusivity is manufactured | | Flâneur | An idle city walker who watches and collects impressions (the Arcades) | Asked whether scrolling a feed is flâneur-like; sharpest line: the feed does the walking, so the user is audience, product and data at once | | Ownership of the Apparatus | From "The Author as Producer": what matters is whether a work changes the apparatus of production | Became Run 000's thesis: the AI question is about who owns the apparatus, not authenticity |

The readings behind them are in the Benjamin Reading List. It was written from general knowledge and is unverified.

The method

  • Roles: Defender, Framework Skeptic, Materialist, Practitioner, Historian of the Concept, Reverse Devil's Advocate.
  • Playbook: one question with a tension; 3 or 4 roles plus a separate moderator; a fresh chat per model; the organizer only carries text and does not steer; one question per round, same full transcript to every model.
  • Evaluation Checks: question answered, reasoned changes, real disagreement, novelty, framework challenged, honesty, specificity. A run failing Novelty and Real disagreement is a summary, not an insight.
  • From Thesis to Essay: how a debate thesis becomes an essay with checked sources.

Status

Run Date Result
Run 000 2026-11-05 Unstructured baseline across Gemini, ChatGPT and Claude (critic). Thesis moved to ownership of the apparatus. Failures seen: easy concession, drift, unchecked attributions, a critic assuming the organizer's position, personal context leaking in. Scored against the checks: question answered late, weak disagreement, partial novelty, framework never challenged.

Next (open): Run 001 with assigned roles and the playbook. Not yet run.

How this grows

  • A new run: add a page to experiments/ (copy Run 000's fields), score it against the checks, add a line to the log and a row to Status above. Save the raw transcript in assets/ with a reference page.
  • A new role or check: add a page under roles/ or metrics/, then update its index.
  • A new concept to test: write it in Theoretical Research concepts/, then cite it in the table above.
  • Method changes (for example the one-question-per-round step) go in the playbook and the log.
